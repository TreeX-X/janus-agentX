# Lightweight Note index v1

## Problem

The file scan already resolves Note IDs, parses documents, calculates source hashes, and reports invalid files. Consumers still need to rescan or reimplement graph logic to answer backlinks, relation filters, code-reference queries, and simple body search. A committed index or a search database would add a second source of truth for a capability that can be derived from the Note files.

## Decision

`buildNoteIndex` scans one explicitly selected checkout and derives URI/path lookup, formal relations, Markdown mentions, and their separate backlinks. It implements the [WorkFlowX common-read contract](note://d2499d5b-4ceb-4d46-aa3b-18e5c9b86034/c61d7a4e-6f8b-4a2e-9d31-5c7e8b0f2a14). Parsed metadata and execution retain their existing representation. [R1 adoption](note://972afef3-2fc7-49de-a3ee-7e041225d28c/81fc137e-9c56-4d3a-88e4-10f175852c97) moves the shared packages to 0.2.0 and the runtime to the final S1.2 profile. Initiative-only interfaces retain their declared name, direction and optional provider; invalid shapes, duplicates and owners are rejected. This additive metadata stays outside taskContractHash and is available for the later projection layer.

Identity grouping precedes publishing lookups and edges. Every duplicate ID or case-colliding path receives a diagnostic; conflicting records have no first winner in `byId`, `byUri`, navigation, or semantic queries. Unique invalid parsed records remain available in `byId` for write validation. `resolveCheckout` rejects identity mismatches, multiple selected bindings, and unavailable explicit selections.

Each entry has a source path, raw `sourceHash`, and classification: valid, legacy, foreign, malformed, conflicting identity, or unreadable. Legacy recognition uses the established H1 `Agent Note:` marker; other unmanaged Markdown remains foreign. Both stay visible without inventing Note identities. Coverage names the checkout, scan completeness, diagnostics, and a deterministic manifest hash. That hash summarizes observed files; it is neither an atomic filesystem snapshot nor a source hash. Failed enumeration, unreadable files, and blocked symlink escapes/cycles make coverage incomplete. An absent Notes directory is a complete empty scan.

Formal edges preserve all seven types and their criteria/scope/reason. Equivalent parent declarations collapse to one edge with declaration paths retained. Cycles diagnose in the read channel. Resolution distinguishes resolved, unavailable, missing, ambiguous, and invalid; an unbound repository or incomplete scan never proves deletion. Declared external targets remain visible. Backlinks report only this checkout's coverage, and consumers inspect resolution before navigating.

`readMarkdownView` uses CommonMark AST links, including reference definitions and URI autolinks. Code, bare URI text, images, and wikilinks create no mention. Relative links resolve against scanned Notes; fragments remain separate locators, including self links. Non-Note destinations remain ordinary links. Repeated mentions collapse by source/target/anchor while retaining occurrences and destinations. A missing or malformed fragment leaves a resolved Note intact. Headings expose shared anchors: lowercase Unicode letters/numbers/marks, underscores and hyphens, spaces replaced by hyphens, and numeric collision suffixes. Renderers consume these anchors rather than introducing another slug policy.

`sourceHash` aliases the existing raw-file `sha256` from the same `readNoteFile` call as parsed text. `readIndexedNote` confines lazy reads to an indexed path in the selected checkout and returns fresh text, its own hash, the indexed hash, and `matchesSnapshot`. BOM, line endings, metadata, and formatting participate in the hash. A path-only move preserves it. A failed reread requires a rebuild before inferring deletion. CLI show exposes the mismatch; its summary and coverage still describe the indexed snapshot.

Existing metadata, relation, code-path, and bounded substring queries remain. CLI list/search add coverage, excluded-file classifications, read diagnostics, and explicit limit/truncation; show resolves the full URI and rejects ambiguous IDs or basenames. Navigation and locator diagnostics stay separate from mutation-blocking diagnostics, so broken prose links do not veto valid writes. The index remains in memory per command or host cache: no database, committed index, new dependency, background service, schema field, or incremental invalidation protocol is added.

## Alternatives considered

- Add a SQLite or persistent search database - strongest case is faster repeated queries, but it adds lifecycle, migration, and stale-cache failure modes before the corpus size justifies them; rejected.
- Keep only `byId` and path lookup - strongest case is the smallest API, but blueprints cannot answer incoming edges or semantic filters without duplicate scanners; rejected.
- Put excerpts and backlinks into Note frontmatter - strongest case is direct reads, but derived values drift and enlarge the sealed schema; rejected.
- Do nothing / reuse - preserves the current CLI surface, but body search and graph navigation remain host-specific work; rejected.

## Consequences

One shared read boundary now supplies engineering wiki and later blueprint adapters. Search remains bounded substring search. Hosts still own checkout selection, cache invalidation on file/branch changes, rendering, and knowledge-page source approval; this change does not implement JanusX UI or migrate the corpus. A persistent cache warrants reconsideration only after measured scan costs require it.

Verification uses `npm run build -w <workspace>` for harness-core, harness-node, and notes-cli (all passed). `npm run test -w @janus-agent/harness-core` passed 75 tests. The focused harness-node command with `tests/index.test.ts tests/read-index.test.ts tests/resolver.test.ts` passed 17 tests; the notes-cli command with `tests/commands.test.ts tests/cli-run.test.ts` passed 12 tests. These cover all seven formal relation types, mention parsing and resolution, duplicate identities, checkout selection, raw-byte snapshots, incomplete scans, symlink bounds, and write compatibility. The owning Note passes core validation and every codeRef exists.

R1 resolves the two earlier profile/fixture failures. The full suites now pass: harness-core 89 tests, harness-node 47, notes-cli 13. The three package builds pass. New interface tests cover round-trip preservation, legal unbound needs, explicit providers, invalid shapes/owners/duplicates and unchanged hashing. Cross-repository adoption evidence and independent review belong to the R1 task; these checks do not claim that JanusX wiki, composition or migration is complete.
