# Agent Note: 保持搜索证据完整并限制无效续跑

Status: implemented

## Problem

简单修改的成本取决于定位所需的模型轮数。若上下文层按字符切掉最新读取内容，却保留工具原有的行号和下一页位置，模型会跳过未见代码。搜索 JSON 的字符截断同样会丢失覆盖范围。重复注入文件正文、按历史失败催促修复以及无进展的 todo 续跑会继续放大输入总量。

## Decision

工具生产端负责限制输出。读取默认返回 100KB 以下全文、以上文件最多 800 行或 48KB，页边界落在完整行之间；上下文保留可容纳的最新结果，不再二次截断正文或 JSON。只有当前工具批次本身超出预算时，模型才收到明确的 `outputOmitted` 结果、原调用和缩小范围后从同一起点重读的指引。最新用户要求和工具调用参数不能被静默丢弃。

LoadedContext 只存文件身份和范围，最多保存 100 项；模型最多得到三个缺失结果的元数据提示，提示放在历史之后，并仅使用剩余预算。已有工具结果携带对应哈希时不重复注入。旧工具正文先转成摘要，再决定是否丢弃历史和调用总结模型。预算计入消息包装、工具参数和实际 JSON Schema，并对非 ASCII 字符采用较保守的估算。

`workspace.search` 优先使用 ripgrep 枚举遵循 ignore 规则的文件，再筛除敏感路径并按显式文件列表搜索。正向 glob 在枚举之后过滤，避免覆盖 `.gitignore`。文件名模式、glob、正则及大小写选项帮助缩小范围。输出最多 100 个完整记录（默认 30），记录预算为 40,000 字符（内容命中带上下各两行上下文与文件哈希，见[读分页放大量级](./2026-09-16-read-paging-token-amplification.md)）；扫描上限和结果截断都有说明。缺少 rg 时，Node 降级支持字面搜索和文件筛选，并明确报告不应用 ignore 文件；正则请求明确要求安装 rg。

todo 在同一进度状态下最多提醒一次。修复提醒只检查最近一批工具结果；后续成功批次消费前面的失败，不把历史 trace 当作待办。相同参数的失败调用在该回合被拦截，重复坚持同一调用则终止；`TARGET_CHANGED` 允许按原参数重新读取。上下文溢出重试从失败的模型调用边界恢复，已完成工具不能重放。系统提示对简单修改直接要求搜索、读取、修改、验证，并避免重复列出 schema 已提供的工具描述。

输入用量按模型调用累计；供应商提供缓存命中数时，CLI 单独显示 cached 部分，不能从输入总数直接推算未缓存费用。分页契约见[行号分页](../feature/2026-09-15-workspace-read-line-pages.md)，工具顺序和推理用量见[上下文效率](../feature/2026-09-15-context-efficiency.md)，任务列表语义见[todo 连续执行](../feature/2026-09-15-todo-continuous-execution.md)。

## Alternatives considered

继续缩小每条工具结果能直接降低单轮输入，但会破坏可编辑的精确证据，并让分页元数据与正文不一致。保留最新完整结果、按年龄和实际预算压缩旧结果，更符合完成任务的总成本目标。

直接让 rg 扫描整个目录能减少子进程次数，但需要复制敏感路径政策为另一套 glob。先枚举、过滤、分批搜索复用现有政策，代价是超大仓库有额外文件枚举和进程开销。

Do nothing / reuse：既有截断与全量重放实现简单，且无需新增依赖；代价是可复现的漏行和额外续跑。JSON Schema 转换复用仓库已有的 `zod-to-json-schema`，作为编排包的显式依赖，避免自行维护 Zod 内部结构遍历。

## Consequences

验证覆盖 200 行读取中的第 150 行、搜索 JSON 完整性、旧输出先 prune、schema 和编辑参数预算、ignore/glob 组合、无 rg 降级、失败后成功不续跑、todo 无进展退出以及真实 SDK 缓存用量透传。命令为 `npm run test --workspace=@janus-agent/agent-core`、`--workspace=@janus-agent/chat-core`、`--workspace=@janus-agent/janus-agent` 和 `--workspace=@janus-agent/cli`，类型检查使用 `npm run typecheck`。

上述四包分别为 307、59、26、345 项通过，执行核心有 1 项跳过；类型检查覆盖全部八个 workspace。CLI 文件预览断言匹配带 checkpoint 的现行标题，审批回归验证相同失败创建调用不会再次弹出审批。新增溢出恢复用例验证工具只执行一次，新增前置条件修复用例验证创建文件后可按相同参数重新读取。

token 预算仍是估算，供应商 tokenizer 和消息包装可能不同。读取完整页可能增加某一轮输入；收益目标是减少遗漏证据导致的补读轮次，不能据此承诺真实模型费用下降比例。rg 需要在运行环境 PATH 上可用；降级不提供同等搜索性能。每个 rg 进程有 15 秒超时，文件枚举上限为 20,000；达到限制应缩小范围。不同语言下的“阻塞”正文不做关键词猜测，重复纯文本最多得到一次 todo 提醒。成功修改或命令执行会清除失败调用记录，允许修正代码后重跑同一测试。

固定的 100 行读取样本中，序列化上下文为 2,529 字符，正文出现一次；相同输入在字符截断与正文注入机制下为 4,685 字符，正文出现两次。这是结构性去重的样本测量，不是供应商 token 或计费基准。
