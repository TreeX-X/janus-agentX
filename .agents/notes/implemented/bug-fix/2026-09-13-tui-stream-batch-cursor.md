# Agent Note: 流式输出时输入框光标合批稳定

Status: implemented

## Problem

流式输出期间输入框保持可编辑，边想边打的字不会丢失。代价是每个 `text_delta` 触发一次全屏重绘加一次原生光标搬家，终端在输出区底部与输入框之间来回跳，人眼看到光标闪动而非稳定停留。`Activity` 转圈每 120 毫秒重绘一次，在工具执行无文本增量时仍以 8 帧每秒搬动光标，放大闪动。

## Decision

`App` 的 `runTurn` 事件入口区分高频增量与低频事件。`text_delta` 与 `reasoning_delta` 进入 50 毫秒窗口队列，窗口内到达的增量按到达顺序一次提交，`React` 批处理合并为单次渲染；工具调用、执行起止、模型结束与错误等事件先排空队列再立即提交，流顺序保持不变。`sendTurn` 返回与异常路径在 `turn-done` 之前排空队列，缺失 `stream_end` 的传输也不会丢尾。卸载时清定时器并丢弃队列。

`Activity` 计时从 120 毫秒放宽到 250 毫秒，转圈步进同步到同一粒度。时长显示精度降到 0.25 秒档，换来工具执行阶段重绘减半。

`useSyncedCaret` 保持每次提交后重测。生产环境定高布局下输入框原点稳定，重测命中相等守卫而不产生二次渲染；测试环境的自适应高度依赖该重测跟随内容下移，收紧依赖会使调整尺寸与多行用例失效，所以不做改动。减渲染的全部收益来自合批与转圈放缓，不碰光标协议。

## Alternatives considered

- 保持现状、逐 token 直发渲染：零延迟、零新增状态；高频重绘加光标两段式定位的闪动保留，ConPTY 与慢终端下最明显，无法满足边输出边输入的稳定要求。
- 隐藏流式期间的原生光标、转完再显示：重绘次数不变，输入中的用户失去插入符与输入法锚点；忙时可编辑是既定行为，隐藏属于降级。
- 把合批窗口设为 200 毫秒以上：重绘更少；首字延迟进入可感知区间。50 毫秒约一帧到三帧的延迟，落在人类无感区间而渲染量降一个数量级。
- 同时收紧 `useSyncedCaret` 重测依赖：省掉每次提交的 `measureElement` 调用；自适应高度下原点跟踪丢失，`tui-cursor.test.tsx` 的调整尺寸与编辑用例覆盖的正是该路径，风险大于收益。

## Consequences

流式文本的最坏首屏延迟增加 50 毫秒，`Activity` 时长显示粒度变为 0.25 秒。队列只存窗口内的增量事件引用并在提交后清空，内存占用随窗口线性封顶；定时器与队列的所有权归 `App` 组件，卸载路径同步清理。`packages/cli` 全量 322 个用例通过，含排队顺序、中断恢复、`Esc` 取消与光标归属用例，命令为在 `packages/cli` 执行 `npx vitest run`，类型检查为在仓库根执行 `npm run typecheck --workspace @janus-agent/cli`。
