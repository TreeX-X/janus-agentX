# Agent Note: 输入框约束拖拽框选（上报开启时）

Status: implemented

## Problem

终端原生拖拽没有空间约束。框选输入框文本时边框、提示符与补齐空格一起进剪贴板，粘回去全是框杂物。键盘选中虽精确，鼠标用户拿不到干净文本。

## Decision

上报开启（`JANUS_MOUSE=1`）时拖拽归应用，选区构造上只含缓冲内容。`MOUSE_ENABLE` 追加 `1002` 按键拖拽跟踪，不碰 `1003` 悬停。默认关闭不上报，原生拖拽保持原样，约束拖拽只活在手动开启里。

坐标原点走 CPR 懒查询。`App` 在首次按下时快照插入符、框位置与终端尺寸并写 `\x1b[6n`，回显行列减快照即终端到 Ink 平移，缓存到几何变化为止。回显与快照对不上则带新快照重问，最多两次后丢弃整笔手势，宁可不选不错选。插入符常驻输入框且框底部 pinned，流式输出不搬动原点，查询实际上按次付费。待回显事件按序缓冲，落定后依次放行。

映射只认内容。`Composer` 发布框几何并暴露 `mouseControl`，`App` 只做分词、路由与原点。`bufferOffsetAtCell` 把单元格解到缓冲偏移，边框直接丢弃，提示符侧与补齐侧钳到行首行尾，窗口标记永不参与。同一 `rowWindow` 同时喂高亮绘制与鼠标映射，两边不可能看到不同的可见行。松开自动经 OSC52 加应用内缓冲复制并保留高亮，点击（无位移）只落光标。

并发语义收敛在引用上。按下与松开同块到达时锚点与末端走 ref，不依赖 React 批提交顺序。生产路径每个 stdin 块经 discrete 更新同步落盘，键盘后读必新鲜。 混合块（鼠标加文本同块到达）整体丢弃，沿用既有尽力语义。路由与回解均以手动开启为门，无上报时注入字节不建查询不建选区。CPR 写 TTY 门控，管道永不见查询字节。

讨论区按下 swallowed。`1000` 下它本来就没有原生复制，约束拖拽只做输入框，不为讨论区建绘制行到原文的脆弱映射。`/help` 鼠标行同步两种模式的取舍。

## Alternatives considered

- 切 alternate screen 拿固定原点 — 坐标零成本；但 Ink 输出协议整体改变，既有光标用例按相对位移断言，全套重写，得不偿失。
- 纯原生加文档 — 零代码；但框杂物是终端行为，文档消不掉，诉求无解。
- 按下时关上报、按键时重开 — 中途关上报救不回当前手势（终端没见过按下就不起选区），松开事件又不可见，只能靠计时器猜，何时重开永远是错的。
- 应用内讨论区逐字复制 — 要给每绘制行建原文登记，Markdown、截断卡与换行稍偏即错，且截断内容本就不全，投入产出比过低。
- Shift 加拖拽旁路 — 各终端有无不一，没被发现等于不存在。
- Do nothing / reuse — 留着键盘选中，零成本；代价是鼠标拖拽永远带框，本轮诉求无解。

## Consequences

- **Gains**: 上报开启时拖拽只框输入框内容，松开即进系统剪贴板，无按键无模式。守卫为 `npx tsc --noEmit` 加 `npx vitest run`（均在 `packages/cli`，32 文件 292 用例全过，新增 17：解析 8、映射 5、Composer 拖拽 3、App 端到端 1，另默认吞没 1）。端到端用例以插入符实测位置自洽回显，断言 SGR 按下、拖拽、松开直达 OSC52；绝对原点真值只活体终端可验，测试覆盖数学闭环加单元。
- **Costs and limits**: 只活在 `JANUS_MOUSE=1` 下，默认原生拖拽仍带框（终端限制，无解）；上报开启时讨论区原生复制停用（`1000` 下本来就没有）；CPR 不支持或几何不收敛的终端丢弃手势，键盘选中不受影响；超 256 事件的巨型拖拽丢弃。当渲染方案暴露点击坐标或终端普及免上报滚轮时重访本决策。

本决策把 [2026-09-11-composer-mouse-select-mode](./2026-09-11-composer-mouse-select-mode.md) 里否决的应用内拖拽以收敛形态落地（底部 pinned 稳定加懒查询替代每帧问询），旧 Note 的脆弱性判断被本实现取代，其余结论不变，两边互链。
