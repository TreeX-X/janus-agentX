01一句话原理：三件套视图

每次发给模型前，buildContext 把持久历史重建成一个能塞进窗口的视图。压完之后模型只看到三样东西，按固定顺序排列：

① 摘要 summary一条 user 口吻的交接语单版、8000 字符封顶。七节模板：目标 / 约束 / 进展 / 决策 / 下一步 / 关键上下文 / 相关文件。口吻是 notes-to-self：resume，不重做已完成工作。
↓拼在 evidence 之后
② 精确 digest一段代码拼的 handoff，不经 LLM 改写path、sha256 前缀、搜索 query、条数，最近 24 行。sha 失真即 edit 冲突，所以这段永远由代码原样拼接。
↓对 window 校验（summary 只扣一次，避免重复扣费）
③ 最近 tail 原文最新 turn 原样保留tool 调用与其结果永不拆开，系统消息永不进压缩 head。持久历史本身从不删除，视图只是视图。

为什么摘要是 user 身份而不是 system？系统区是每 turn 重读的安全规则位，摘要只配做 handoff，不配进安全区。

02触发线：预算公式与 90% 硬顶

触发预算 = 窗口减去输出预留，再减去安全垫，最后套一层 90% 天花板。调用方只能把线提前，不能推迟：

// budgetFor：缺省行为与过去完全一致，大窗口才被天花板接管
budget = min(window − reserved − buffer, floor(window × 0.9))
reserved = min(maxOutputTokens, 2048)   // 输出预留
buffer   = 缺省 512，可配，钳制在 0～10% 窗口  // 只许调早
tail + evidence：能用
摘要预留
输出预留 + 垫子
90% 硬顶
0context window

小窗口（16k 一档）下 min 左边更小，行为与过去逐字一致，旧单测零改动；大窗口（200k / 1M）下右边接管，任何偏晚的配置都撞顶。窗口来源是随仓内置表（未知模型回落 16384 并在 /status 明示 estimated），运行时零网络。

03压什么：切分规则与三层封顶

切分永远按 turn 边界从新到旧累加 token（len/4 口径），直到预算塞满。 tool 结果中间永不断开；单个 turn 超预算，允许整块滑入被丢弃 head，而不是抛错杀死会话。

进摘要前逐条截断

tool 输出每条压到 2000 字符，head 全文封顶 24000 字符：摘要调用自己先不能溢出。

存下来只留一版

摘要 8000 字符封顶，旧版丢弃。头指纹对全文寻址：同一 head 永不重复烧调用。

模板缺节纠正一次

缺 Goal / Progress / Next Steps 就追问一次，再缺判失败，走 digest 老路。

迭代最多 3 轮

新摘要占位可能又挤掉旧 unit，下一轮继续吸收，直到所有被裁内容都有归宿。

04双轨：精确 digest 与 LLM 摘要的分工

digest 轨 · 保真

toolDigest + droppedTurnsHandoffMessage + LoadedContextIndex（最近 3 个已读文件 × 6000 字符）。path / sha / range / 条数一个字符都不许 LLM 碰，workspace.edit 的 expectedHash 靠它活着。

摘要轨 · 保义

只讲正文：要做什么、做到哪、卡在哪、下一步。文件清单由代码侧拼在摘要尾部（读写各最多 20 条），模型负责讲故事，不负责记路径。

LLM 改写 sha 是 edit 冲突的第一来源。分工铁律：事实走代码，叙事走模型，两者拼在一起呈现，永不混写。

05兜底链：失败、超大单轮、provider 溢出

自动 · 每轮发送前试压transformContext：maybeCompact → buildContext指纹去重让重复调用零成本；无 summarizer 时退化为纯 digest，与从前一致。压缩永不抛错打断 turn。
↓单个 turn 比整个预算还大时
超大单轮 · 滑入 head，不抛错digest 照样给出一行精确记录，force 下可被摘要吸收过去这里抛 CURRENT_TURN_EXCEEDS 停轮；现在只有系统消息超限才抛 SYSTEM_CONTEXT_EXCEEDS_BUDGET。
↓provider 说窗口爆了（context / overflow / 413…）
溢出 · 同 turn 强制压 + 重试一次第二次溢出直接返回错误，不循环重试复用初始消息（loop 从不改输入数组），已执行 tool 痕迹保留。估算偏差由保守提前压 + 这一次重试共同兜住。

06手动挡：/compact 与聚焦语

/compact [focus] 在任务边界主动压，不依赖 turn，auto=false 照样可用。focus（500 字符内）只做强调语写进提示词，不删减其它章节——手动压的是时机，不是偷工减料。短历史、已是最新、传输缺失、摘要非法各有明确回执，落盘后重启与切换会话自动回填。

07旋钮表：只留两个，其余写死

项值为什么这样定
bufferTokens缺省 512，钳 0～10%唯一的触发旋钮，只能提前。调晚的自由就是溢出的自由，不给。
keepRecentUnits缺省 1，钳 1～50，仅 force手动压时留几个最新 unit 原文，仅此而已。
tool 截断 / head 封顶 / 摘要封顶2000 / 24000 / 8000硬编码。不值得配，配了也不会调，抄 opencode / pi 的实测数。
digest 行数 / evidence24 行 / 3 文件 × 6000 字符硬编码。精确轨的预算，动它不如动 buffer。
可观测getLastCompactionInfo最近一次 tokensBefore + 摘要长度，给 /status 与日志用，压缩不再是黑箱。

08刻意不做的三件事

用量回路（max 本地估算 / 上轮用量）

要打通 stream 适配器与压缩之间的用量 plumbing，多一堆状态，少一次误判。保守估算 + overflow 单次重试已覆盖，延后。

loop 边界中途压 + pending 重放

要动 agent loop 主干、重建请求。preflight + overflow 重试覆盖了常见长链，重放语义等真痛再做。

split-turn 双摘要 / provider 原生压缩 / 自动重读文件

双摘要是质量上限不是存活下限；原生压缩无统一 endpoint；压后自动重读会引发压缩雪崩。evidence 按预算重建即可。
